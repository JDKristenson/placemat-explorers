# Contributing

Keep the app small, local-first and useful at a family table.

- Use generic examples. Never include real children's details or generated family pages in issues, screenshots, tests or commits.
- Do not add analytics, persistent profiles, account systems or background network requests without a clear privacy design and review.
- Keep all age and activity logic on the device. City lookup and forecast requests must remain optional and explicit.
- Preserve manual printing. No printer discovery, scheduled jobs or automatic submissions.
- Use original or clearly licensed assets. Record any added attribution.
- Make prompts kind and flexible. Activity levels are not assessments, and children develop differently.
- Run the tests and public audit before submitting changes. Preview all four age bands in a browser, check failed and repeated weather requests, and check landscape print preview on Letter and A4.
- Update the public-file allowlist deliberately when adding files. Never weaken it simply to include generated output.

New features and bug fixes can be proposed through repository issues or pull requests. Do not post a security issue with live secrets or personal information. See SECURITY.md.
